# HE1 rulings, HE1 Task 24: ClickHouse type rules

Rulings made while executing Task 24 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R24.1, R24.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R24.1 | **How an expression's ClickHouse type is carried.** After the rule `ClickHouseCoercion` (`loams-house-sql/src/coerce.rs`), an expression's ClickHouse type is its Arrow field's: the `loams.ch.type` metadata when it matches the Arrow type, else the type inferred from Arrow, `Nullable` when the field is. Where Arrow alone would read another type (a `Date` is `Date32`, an `Enum8` is `Int8`, a `CASE` field has no metadata), the expression is wrapped in a cast to its own Arrow type whose explicit target field carries the type (`coerce::tag`): DataFusion copies an explicit cast field's metadata and drops a type-only one's. `CAST(x AS T)` gets the same field from the type planner (`plan_type_field`). The one exception is a predicate (a comparison, `AND`, `IN`, `LIKE`, `IS NULL`, …): it stays an Arrow `Boolean` inside conditions, its ClickHouse type (`UInt8`, or `Bool` when an argument of `and`/`or`/`not` is exactly a `Bool`, FunctionsLogical.cpp) is decided by its kind, and it is cast to `UInt8` wherever it becomes a value (an output column, an operand, a function argument). The engine's answer takes its schema from the analyzed plan, so the optimizer cannot drop a type | Plan HE1 Task 24 (output types) | Medium: a later task's UDF that returns an ambiguous Arrow type must set `loams.ch.type` in its return field |
| R24.2 | **The rule runs before DataFusion's `TypeCoercion`, which stays** (`coerce::analyzer_rules`: `ResolveGroupingFunction`, `ClickHouseCoercion`, `TypeCoercion`). Every operator this rule types leaves with both operands of one Arrow type, so `TypeCoercion` changes nothing there; it still coerces function signatures (Tasks 28–33). Operators stay `BinaryExpr`s over operands cast to the computing type, so pruning and pushdown keep working; DataFusion's integer kernels wrap (`add_wrapping`), as ClickHouse's do. Only `intDiv`/`intDivOrZero` are functions (`loams-house-exec/src/ops/int_div.rs`) | Plan HE1 Task 24 | Low |
| R24.3 | **Two plan-time shims.** `SqlToRel` checks types before any analyzer rule: a `Filter` must be boolean, `AND`/`OR` take booleans, a boolean is no arithmetic operand. A `WHERE`/`HAVING` condition that is not syntactically boolean is wrapped in `__ch_cond(…)` (`coerce::mark_conditions`, after the guard), which the rule replaces with `x != 0`; an `ExprPlanner` (`ClickHouseOperators`) turns a number operand of `AND`/`OR` into `x != 0` and a boolean operand of arithmetic or of a comparison with a number into `UInt8`. Measured: `WHERE`/`HAVING`/`and`/`or`/`not` take any number, a float included; a `String` is `59` in `WHERE` and `43` in `and`; a `CASE`/`multiIf`/`if` condition must be `UInt8` (`Bool`, `Nullable(UInt8)`), else `43` | Oracle, `corpus/he1/24/cases/bool_*` | Low |
| R24.4 | **Measured rules.** Literals: non-negative integers are the smallest unsigned type (`9223372036854775807` is `UInt64`, `-0` is `UInt8`), negative ones the smallest signed type, `2^64` and up `Float64`. `+`/`*` widen one step up to 64 bits (`NumberTraits::nextSize`), `-` is always signed, `/` is `Float64`, `%` is signed with the next size of the divisor when the dividend is signed and the divisor's type otherwise, `intDiv` has the dividend's width and is signed when either is; `Bool` is `UInt8` throughout. Decimals: `D op D` has the wider storage's full precision (`Decimal(5,2)+Decimal(5,2)` is `Decimal(9,2)`), `D op integer` keeps the decimal's type, `*` adds scales, `/` truncates to the dividend's scale (`2.00/3` is `0.66`), a float makes `Float64`. `Date ± n` is days, `DateTime(64) ± n` seconds, `Date - Date` and `DateTime - DateTime` `Int32`. Comparisons are exact across signedness (`UInt64` against a signed type compares as `Decimal(20, 0)`), and a string constant is read as the other operand's type (`53 TYPE_MISMATCH` when it is not a value of it; an integer column takes any integer text, `u8 = '300'` is `0`); an `Enum` against a non-element name or a string column compares by name. Supertypes follow `getLeastSupertype` (`Bool` equals `UInt8`, so the first of them wins; decimals of one width are equal; `LowCardinality` survives only when all are) | Oracle, `scripts/house/gen-type-cases.py` | Low |
| R24.5 | **`48` where ClickHouse 26.9 answers a `Variant`** (no common type: `[1, 'a']`, `if(c, toUInt64(1), toInt64(-1))`, `UNION` of `String` and a number), since `Variant` has no Arrow layout (R21.3); a comparison with no common type is ClickHouse's `386`. `Decimal % integer` is `48`: 26.9 reads the integer as the decimal's raw ticks (`toDecimal32(7.5, 2) % 2` is `0`), which the engine does not copy. Arithmetic on `Decimal256` and `intDiv` of a `Decimal128` (`Int128`) are `48` | Oracle | Low: each is in the corpus with its triage |
