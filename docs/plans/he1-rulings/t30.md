# HE1 rulings, HE1 Task 30: Functions I: date and time

Rulings made while executing Task 30 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R30.1, R30.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R30.1 | **Each date and time function is a `ChFunction`** (`loams-house-exec/src/func/datetime/udf.rs`): a `ScalarUDF` with a user-defined signature that coerces nothing, typed in `return_field_from_args` from the arguments' ClickHouse types (`loams.ch.type`, else inferred from Arrow) and constant arguments, and returning a field that carries the result's ClickHouse type (`DateTime('Asia/Kolkata')`, `DateTime64(3)`, `IntervalDay`). NULLs follow ClickHouse's default implementation: a `NULL` literal argument makes the result `Nullable(Nothing)`, a `Nullable` argument makes it `Nullable`, and a row with a `NULL` argument is `NULL`. `now()`/`now64()` are `Stable` and fold to the query's start time, so every call in a query agrees. The module registers through `func::datetime::register(&mut Registry)`, one line in the engine's `registry.rs`; Tasks 31–33 can reuse `ChFunction` | Plan HE1 Tasks 30–33 | Low |
| R30.2 | **Time zones: the function's zone argument, else the value type's own zone, else the session's.** The session zone is DataFusion's `datafusion.execution.time_zone` when it names an IANA zone, else UTC (the engine's default, and the oracle's server zone). Task 37 sets `execution.time_zone` from `session_timezone`; nothing else changes. Zones come from `chrono-tz` 0.10.4, which carries **IANA tzdata 2025b**; the oracle reports `TZDATA_VERSION` **2026c**. The releases between change no rule of `UTC`, `Asia/Kolkata` or `America/New_York`, the zones the corpus uses; a `chrono-tz` that carries 2026c is taken once it is 14 days old. Rounding follows `DateLUTImpl`: `toStartOfInterval` by seconds and minutes counts from the epoch in zones whose offsets were whole hours (minutes) since 1970, else from the local midnight; multi-hour intervals count from the local midnight; `dateDiff('hour')` uses `toRelativeHourNum`'s offset-at-epoch rule | Oracle (`system.build_options`) | Low: a zone whose rules changed between 2025b and 2026c answers by the older rules until the bump |
| R30.3 | **Date arithmetic is planned, not coerced.** `INTERVAL n UNIT` is rewritten by the front end to `toIntervalUnit(n)` (`loams-house-sql/src/temporal.rs`; `INTERVAL '1 day'` too), and `EXTRACT(f FROM x)` to `toYear(x)` and so on. `Registry` gains `expr_planners`, which `HouseContext::get_expr_planners` returns; `DatePlanner` plans `plus`/`minus` whose operands are a date or time and an interval or a number as ClickHouse resolves them: `addUnits`/`subtractUnits` (a number moves a `Date` by days and a time by seconds), and `t1 - t2` as `__ch_date_minus` (`Int32` days or seconds, `Decimal(18, P)` for `DateTime64`). Every other operator stays a DataFusion `BinaryExpr` for Task 24's rules. An interval in `*`, `/` or `%` is `43`, as ClickHouse answers; an interval plus an interval (a tuple of intervals in ClickHouse) is `48` | Plan HE1 Task 30 ("implement plus/minus with intervals inside your UDFs"); Task 24 keeps operators as `BinaryExpr` | Low: Task 24's analyzer sees only UDF calls here |
| R30.4 | **Bound parameters as constants.** A date and time function reads its scale, zone, unit and format as constants while it plans. A bound parameter arrives as `_CAST(v, 'T')`, which DataFusion does not treat as a constant, so the front end folds a cast of a literal to `String` or an unsigned integer type into the literal, in these functions' arguments only (`temporal::fold_constant_args`). A cast to a signed type stays: ClickHouse refuses `toDateTime64(x, _CAST(3, 'Int64'))` with `43` (the `toDecimal()` scale must be unsigned), and so does the engine | Oracle, `he1-30/to_datetime64_bound` | Low |
| R30.5 | **Ranges, as measured.** A `Date` from text or a number saturates to 1970-01-01..2149-06-06 (a number below 65536 is a day number, above it a Unix timestamp), and from a `Date32` or `DateTime64` it wraps as a `UInt16`. A `DateTime` from text or a number saturates to the `UInt32` range, and from a `Date32` or `DateTime64` it wraps. `Date ± days` wraps as a `UInt16` and `DateTime ± seconds` as a `UInt32`; `Date32` and `DateTime64` do not wrap. The `toStartOf*` results clamp to their type's range. A fractional interval count is truncated. `toDate('…T…')` is `6`, bad text is `38` (dates) or `41` (times), an unknown zone `36` | Oracle, `corpus/he1/30` | Low |
