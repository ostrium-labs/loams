# HE1 rulings, HE1 Task 32: Functions III: arrays, maps, tuples, lambdas

Rulings made while executing Task 32 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R32.1, R32.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R32.1 | **Functions whose lambda is optional are higher-order functions only.** `arraySum`, `arraySort`, `arrayReverseSort`, `arrayCount`, `arrayExists` and `arrayAll` (and every lambda function: `arrayMap`, `arrayFilter`, `arrayFirst`, `arrayFirstIndex`, `arrayLast`, `arrayLastIndex`, `mapFilter`) are `HigherOrderUDF`s in `Registry.higher_order` (`loams-house-exec/src/func/lambda`), which also take the plain form (`arraySum(a)`): DataFusion 55 looks a scalar function up first, so a scalar of the same name would never see the lambda. The lambda comes first, takes one parameter per array, and arrays of different lengths on a row are `190` | DataFusion 55's `sql_function_to_expr` order | Low |
| R32.2 | **`mapFilter` with a one-parameter lambda gets the entry as `Tuple(K, V)`** (Langfuse v3: `mapFilter(x -> … x.1 …, m)`), with two parameters the key and the value. DataFusion does not tell a function how many parameters its lambda declares, so the guard renames the one-parameter form to `__ch_mapFilter_tuple`. Lambda parameters are quoted by the guard, so DataFusion keeps their case | Mined use; `FunctionMapToArrayAdapter` | Low |
| R32.3 | **Literals and subscripts become the House's functions in the guard**: `[…]` is `array(…)`, `(a, b)` is `tuple(…)`, `{'k': v}` is `map(…)` (`__ch_map`), `a[i]` and `m[k]` are `arrayElement(…)`, `x.name` after a subscript is `tupleElement(x, 'name')`. DataFusion's own array and struct planners are not registered, so nothing reaches them. Slices (`a[i:j]`) are `48` | Plan HE1 Task 32 | Low |
| R32.4 | **NULL and LowCardinality follow ClickHouse's default implementations** (`IFunction.cpp`) in `func/nested::Composite`: a `Nullable(Nothing)` argument makes the result `Nullable(Nothing)`, a `Nullable` argument makes it `Nullable`, all-`LowCardinality` arguments make it `LowCardinality`. `array`, `tuple`, `map`, `has`, `indexOf`, `hasAll`, `hasAny`, `mapContains`, `arraySlice` and `tupleElement` see `NULL`s themselves; values compare on Arrow's row format, where `NULL` equals `NULL` (`has([NULL], NULL)` is 1). `arraySlice` reads a `NULL` offset as 1 and a `NULL` length as unbounded (GatherUtils). `arrayDistinct` drops `NULL`s. Supertypes are Task 24's `least_supertype`, maps key by key and value by value | ClickHouse sources | Medium: each is checked by `corpus/he1/32` once the oracle job runs |
| R32.5 | **Not yet measured on the oracle (owner's no-build rule, 2026-10-27).** These follow ClickHouse's sources and docs and wait for the CI oracle job: `arraySum` of `Nullable` elements is `43`; `arraySort` is stable with NaN after the numbers and `NULL` last (descending too for `arrayReverseSort`); `arrayCount`, `arrayFirstIndex` and `arrayLastIndex` are `UInt32`; `arrayStringConcat` writes non-string elements as `toString` does; `tupleElement` out of range is `127 ILLEGAL_INDEX` and an unknown name `10`. Mismatches are triaged in `triage.toml` from the CI run | Owner rule | Medium |
| R32.6 | **`arrayJoin` as a function is typed (its element type) and refused with `48` when it runs**, until Task 35 hoists it into the row-multiplying operator; never answered as if it were a scalar. **`untuple`**: Task 25's scope expands it for a column or a tuple literal; for any other expression it is left as a select item and expanded after `SqlToRel` (`loams-house-sql/src/untuple.rs`), each element named `tupleElement(<t>, '<n>')`, or `<alias>.<n>` under a client's alias | Plan HE1 Tasks 25, 35 | Low |
