# HE1 rulings, HE1 Task 25: Name resolution

Rulings made while executing Task 25 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R25.1, R25.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R25.1 | **Syntax sqlparser 0.62 cannot read is rewritten as text first** (`loams-house-sql/src/rewrite.rs`, at the start of `lex::pre_pass`, on sqlparser's own tokens by byte range): the ternary `c ? a : b` becomes `if(c, a, b)`; a scalar `WITH expr AS n` becomes a marker CTE `n AS (SELECT expr AS __ch_with)`; an alias inside an expression becomes `__ch_alias(expr, n)`; a matcher's transformers that sqlparser cannot read (`APPLY`, transformers after `COLUMNS`, `EXCEPT STRICT`, an out-of-order `EXCEPT`/`REPLACE`) become one `REPLACE (…)` list of markers. The guard lets the markers through and `scope` consumes them; none reaches `SqlToRel` | Plan HE1 Task 25 (the ternary in `lex.rs`) | Low: a marker that leaks is an unknown function, never a wrong answer |
| R25.2 | **Name resolution is an AST rewrite after the guard and before `SqlToRel`** (`loams-house-sql/src/scope.rs`, called from `plan::prepare`, before Task 24's `mark_conditions`). Aliases are substituted where used, in every clause (select items, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`, `JOIN … ON`); an alias shadows a column (`prefer_column_name_to_alias = 0`); inside its own definition, and in any alias it leads to, the name is the column again; lambda parameters shadow both; one alias with two different expressions is `179 MULTIPLE_EXPRESSIONS_FOR_ALIAS`. Scalar `WITH` shadows columns at its own level; in a subquery that subquery's own columns win | Measured on clickhouse-server 26.9.2.8 (analyzer on), `corpus/he1/25` | Medium: substitution copies the expression, so a heavy alias used twice is computed twice until the optimizer's common-subexpression pass |
| R25.3 | **Matchers expand to explicit select items from the catalog's columns** (`*`, `t.*`, `COLUMNS('re')`, `COLUMNS(a, b)`, with `EXCEPT [STRICT]`, `REPLACE`, `APPLY` applied in order; `untuple(t)` becomes one `tupleElement` per field). A later table's column that clashes is named `t.c`; `USING` columns appear once. `asterisk_include_alias_columns` and `asterisk_include_materialized_columns` take the catalog's columns as they are: the lake tables' column kinds come with Task 26 and the settings with Task 37. Duplicate output names (`SELECT a, a`) are named apart in the plan (`__ch_dupN_name`) and `Prepared::names` gives the engine the real ones | Plan HE1 Task 25 | Low |
| R25.4 | **A subquery is named `_subquery_N`** (R22.2): one counter per statement, in the order the analyzer meets subqueries, measured: scalar `WITH` first, then the `FROM` tree (a derived table, or a reference to a CTE, counts), then the select list, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`; a subquery counts before those inside it; `EXISTS` counts two (`names::subquery_numbers`) | Oracle, `corpus/he1/25/cases/subquery_*` | Low: names only |
| R25.5 | **Snowflake/BigQuery-only wildcard options stay refused** (`* ILIKE`, `* EXCLUDE`, `* RENAME`, `* AS`): ClickHouse has none of them, so they are `48` from the guard, not a later task | ClickHouse 26.9 grammar | None |
