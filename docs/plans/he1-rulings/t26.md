# HE1 rulings, HE1 Task 26: Lake-table reads (`loams-house-iceberg`)

Rulings made while executing Task 26 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R26.1, R26.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R26.1 | **The reader is split: the fork's `iceberg` plans, DataFusion reads.** `LakeTable` (`loams-house-iceberg/src/provider.rs`) opens the pinned metadata with the fork (`iceberg-engine`), plans the snapshot's `FileScanTask`s with the scan's Iceberg predicate and their attached deletes, and hands the data files to DataFusion's `ParquetSource` (filter pushdown, page index and bloom filters on; each file's data sequence number a partition value; Parquet's row number a virtual column). A projection of `Restore` UDFs gives each column its ClickHouse type (`encodings::restore`). The fork's Arrow reader is never used, so no Arrow 58 value crosses into the engine | Plan HE1 Task 26 ("Arrow 59 is shared with DataFusion"; the fork's `FileScanTask` shape) | Medium: a fork upgrade that changes `FileScanTask` breaks `provider.rs` and `deletes.rs` only |
| R26.2 | **Storage is the caller's `object_store`** (`io::StoreStorage`): an iceberg `Storage` (async, `typetag`-registered) over `Arc<dyn ObjectStore>` for metadata, manifests and deletes, read-only, never serialised (a worker builds its own, Task 39); DataFusion reads data files from the same store. Not iceberg's opendal storage: one store, one cache path (house-cache), and S3, RustFS and `file://` alike | Plan HE1 Task 26 ("Storage I/O") | Low |
| R26.3 | **Paths are read under the pin's location.** Every path the metadata names under the metadata's own `location` is read under `TablePin::location` (`io::Paths::rebase`); a `scheme://bucket/key` URL reads `key` of the store. A table can move (fixtures, a restored bucket) without rewriting its metadata | Fixtures; `views.rs` reads by the catalog's location | Low |
| R26.4 | **Catalog expressions are planned by the engine's own front end.** A column's `DEFAULT` (for files written before an `ALTER … ADD COLUMN`), an `ALIAS` and a delete `TTL` are catalog text in ClickHouse's dialect: each must parse as exactly one expression, is printed again from its tree (R11.11), is planned with `loams-house-sql` (its functions and Task 24's type rules) over the table's columns, and a subquery is `497`. The result is a view over `LakeTable` (`computed.rs`) that DataFusion inlines, so filters still reach the scan. `loams-house-iceberg` depends on `loams-house-sql` for this (both engine crates) | HE1 R9.12, R10.6; `views.rs` `casts`/`computed` | Medium: a `DEFAULT` using a function a later task brings is `46` until that task |
| R26.5 | **Columns map to files by Iceberg field id** (`provider::FieldIds`, a `PhysicalExprAdapterFactory`): a renamed column reads its older files, and a column dropped and added again under its old name does not read the old values. A file without field ids is read by name | Iceberg spec (column projection) | Low |
| R26.6 | **Row lineage is read only when the pin asks** (`TablePin::lineage`): `_row_id` and `_last_updated_sequence_number` as plain `Int64`, a row whose file stores no value inheriting the file's first row id plus its position and the file's data sequence number. Never run-end encoded (R11.5: iceberg-rust's reader gives the sequence number as REE) | R11.5; spike `results/lineage.txt` | Low |
| R26.7 | **A column the engine cannot lay out is refused only when read.** Another writer's `variant`, `geometry` or `unknown` field is `ChType::Other`: the table opens, `SELECT` of other columns works, and a scan that names it is `48` (R21.3: `Variant` has no Arrow layout yet). Equality deletes, which the House never writes, are `48` too | R21.3 | Low |
| R26.8 | **The `he1-26` lake fixtures are generated in CI until they are committed.** `regenerate_corpus_26_lake` (ignored) writes `corpus/he1/26/lake` from the oracle's rows with `loams-house-lake`, step by step as the setup made them; the `house-engine-oracle` job runs it when the directory is absent, then `the_corpus_lake_loads_and_reads`, then starts the dev server with `--lake` for every `corpus/he1/*/lake`. A lake table shadows the seeded copy of the same name. Committing the fixtures (`scripts/house/lake-fixtures-26.sh`) makes the job skip the generation | Owner rule 2026-10-27 (no local runs): the fixtures could not be written locally | Low: CI time only |
| R26.9 | **`chdb_written_tables_read_identically` lives in `loams-house-worker`'s tests** (`tests/engine_reads.rs`), which already link libchdb and run in the House job: the House writes the tables (DDL, `INSERT`, `ALTER … ADD COLUMN … DEFAULT`, an `ALIAS`, a delete `TTL`), chDB answers through `views.rs`, and the engine reads the same pins; both answers are `JSONCompactEachRowWithNamesAndTypes`, compared line by line. The engine crates are dev-dependencies of the worker, so `engine_crates_stay_apart` (normal dependencies) still holds | Plan HE1 Task 26 ("needs libchdb … write a ruling") | Low |
| R26.10 | **`spark_v3_tables_read_as_spark` is ignored until its tables are committed.** The HE0 spike kept fingerprints, not tables; `scripts/house/spark-v3-fixtures.sh` writes them with unmodified Spark 4.0.4 + Iceberg 1.12.0 (Hadoop catalog on a local directory, `tests/fixtures/spark-v3/write.sql`) and runs the test with `LOAMS_SPARK_V3_WAREHOUSE`. Expected values are Spark's (`spark-08.txt`) and the counts the SQL implies; the variant and default-value tables are left out (R26.7) | Plan HE1 Task 26 (fixtures from `he0-iceberg-v3-spike`) | Medium: until the tables are committed, deletion vectors and v2 position deletes are checked only by `deletes.rs`'s unit test |
