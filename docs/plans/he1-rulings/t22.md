# HE1 rulings, HE1 Task 22: The front end's core (`loams-house-sql`)

Rulings made while executing Task 22 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R22.1, R22.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R22.1 | **The pre-pass works on sqlparser's own tokens and edits the text by byte ranges** taken from token spans (end exclusive, columns in characters), so literals, comments and quoting reach the parser exactly as written. It takes out `FINAL` after a relation (`FROM`/`JOIN`/`,` + name [[AS] alias]), recorded as (name as written, alias); `GLOBAL` before `IN`/joins; strictness words (`ANY`, `ALL`, `SEMI`, `ANTI`, `ASOF`) before a join, which is refused for now (`48`, Task 35) except `ALL`; and a query's depth-0 trailing `SETTINGS …` and `FORMAT …` (sqlparser reads `SELECT 1 SETTINGS …` as an alias). It also rewrites `t.1` and `(…).1` to `tupleElement(…, 1)`. A `FINAL` sqlparser still reads as an unquoted alias is marked too, never planned as an alias. The ternary `c ? a : b` is not read yet (Task 25) | Dialect spike §2.3, HE0 R2.3 | Low |
| R22.2 | **Column names are ClickHouse's**, measured on the oracle (`tests/fixtures/names.tsv`, 72 expressions, `scripts/house/capture-sql-fixtures.sh`). Operators print as their functions (`plus`, `equals`, `notIn`, …), and `and`/`or` chains flatten. `BETWEEN` becomes `and(greaterOrEquals, lessOrEquals)`, `CASE WHEN` becomes `multiIf`, `CASE x WHEN` becomes `caseWithExpression(…, NULL)` and the ternary becomes `if`. A float literal prints shortest with a trailing `.` when integral (`1e3` is `1000.`). `[1.5, 2]` is `[1.5, 2.]`. `count(*)` is `count()`, with the written case kept (`COUNT()`). `count(DISTINCT x)` is `countDistinct(x)`. `x::T` of a number literal is `CAST('n', 'T')`. A bound parameter is `_CAST(7, 'UInt8')`. A lambda is `lambda(tuple(x), …)`. `t.x` is `x`. A select item without an alias gets the name as its alias (a bare column keeps its own). **Not done:** scalar subqueries are named `_subquery_N` by the oracle (Task 35) | Clients read results by these names | Medium: forms not in the fixture may differ; each new oracle case checks one more |
| R22.3 | **Function names** resolve through `system.functions` of the oracle (`src/functions.tsv`, 1 918 names). A name is case-sensitive unless marked `case_insensitive`, aliases go to their target (`DATE_DIFF` → `dateDiff`), and aggregate combinator suffixes are read longest first (`uniqMergeState`). An unknown name is `46`. Every function identifier is quoted with its canonical name before `SqlToRel`, because DataFusion lower-cases unquoted function names. `map`, `make_map` and `unnest` register as `__ch_<name>`, since DataFusion's planner special-cases those names. `count()` and `count(*)` become `count(1)`, which DataFusion 55's physical planner needs. `CAST(x, 'T')` and `_CAST(x, 'T')` become `CAST(x AS T)` with the ClickHouse type text, which the House `TypePlanner` (`ClickHouseTypes`) maps through `loams-house-types`. sqlparser's spellings (`INT8`, `FLOAT64`, `STRING`, and Postgres's 64-bit `int8`) are written back as ClickHouse's in `context::type_text` | Dialect spike §3.1 | Low |
| R22.4 | **Refused with `48` until their task** (each naming the task): parametric functions (28), `FINAL` (27), `LIMIT BY`, `WITH FILL`, `INTERPOLATE`, `WITH TOTALS/ROLLUP/CUBE` (34), `ARRAY JOIN`, `SAMPLE`, join strictness, `ASOF` (35), `INTERVAL`, `EXTRACT` (30), `POSITION`/`SUBSTRING … FROM`/`TRIM` forms (31), subscripts and map literals (32), `CASE x WHEN` (33), `* EXCEPT/REPLACE/APPLY` (25), table functions (38). `PREWHERE` is folded into `WHERE` now, ahead of it. Statements other than `SELECT` are `48` for the Rust engine. Several statements are `62` | Plan HE1 Task 22 | Low |
| R22.5 | **Stopped here by the owner (2026-10-24)**, with Task 22 in PR and Task 23 not started. Task 23's design, as worked out: `loams-house-engine` gets an `Engine` over an in-memory catalog of seeded tables (ClickHouse types in the field metadata), executing `loams_house_sql::prepare`'s plan with a DataFusion `SessionContext`, plus a `JSONCompactEachRowWithNamesAndTypes` writer on `loams_house_types::text` (JSON style). The dev server is a small loopback HTTP/1.1 server: `POST /` for queries, `POST /loams/seed?database=&table=` taking a Parquet body plus the columns' ClickHouse types in a header, `GET /ping`. The oracle runner gets a target field `seed = true`. After a corpus's setup on the baseline, it lists the baseline's tables, reads `system.columns` and `SELECT * FORMAT Parquet`, and posts each to the seeded target. The engine side converts ClickHouse's Parquet layout to the engine's (`Enum`, `DateTime`, `LowCardinality`, `UUID`, …) with Arrow casts per type: one test per Tier 0 type. Triage entries gain `task = "<N>"`, and `--task N` fails while a `bug` names N. A per-PR workflow runs `corpus/he1/*` with the pinned 26.9.2.8 image as a service container | Owner's stop, 2026-10-24 | None |
