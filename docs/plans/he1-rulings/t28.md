# HE1 rulings, HE1 Task 28: Aggregates, combinators, parametric aggregates and `windowFunnel`

Rulings made while executing Task 28 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R28.1, R28.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R28.1 | **Aggregate names are read as ClickHouse's factory reads them** (`loams_house_sql::aggregates`): a name that is a function itself is never split, otherwise combinator suffixes come off the end, longest first, while the rest is an aggregate (`sumIfArray` is `-Array` over `-If` over `sum`; `sumMap` is `-Map` over `sum`; `countDistinct` is `-Distinct` over `count`). The analyzer's `…IfOrNull` → `…OrNullIf` rewrite is applied (measured: `sumIfOrNull(x, 0)` is `NULL`, `avgIfOrDefault(x, 0)` is `nan`). **Parameters are literals carried in the planned name**: the guard checks each is a number, a string, a negation of one or a bound parameter (else `36`, as 26.9 answers; `309` on a scalar function), and plans `topK(10)(x)` as `"topK(10)"(x)`, so a function's result type and its parameter checks are known at planning time. **The outermost `-If` is DataFusion's `FILTER (WHERE cond)`**; an inner one, or one under `OVER`, is the exec wrapper | Plan HE1 Task 28 | Low |
| R28.2 | **One DataFusion aggregate, `ChAggregate`, per planned name**, made on demand by the registry's `aggregate_factory` (combinations are unbounded, so none are pre-registered), building an `Agg` from the arguments' ClickHouse types as `AggregateFunctionFactory::get` does: top-level `LowCardinality` arguments are read as their values; combinators apply outermost first, each transforming the types for the one inside; wherever an argument is `Nullable`, the `Null` combinator skips rows with a `NULL` and makes the result `Nullable` unless the function returns its default on `NULL`-only input (`count`) or the result cannot be `Nullable` (arrays, maps, tuples); under `-If` the condition's nullability does not count; `-SimpleState` takes `Null` inside it. `DISTINCT` in a call is the `-Distinct` wrapper, so `count(DISTINCT x)` answers `countDistinct`'s (= `uniqExact`'s) value. Every combinator wrapper is generic over the `Agg` it wraps, so Task 29 adds `-State`/`-Merge` the same way (they are `48` naming Task 29 now, as are `uniq*` and `quantile*`) | `aggregate_result_types_match_the_oracle` (1 949 call and type pairs from the oracle) | Low |
| R28.3 | **`groupUniqArray` and `-Distinct` keep values in the order first read.** ClickHouse returns them in its hash table's iteration order (CRC32/`intHash64` buckets), which it does not specify; the corpus pins only cases whose order is defined (one or two distinct values in table order). Matching ClickHouse's hash order is possible (port `HashSet` and its hashes) if a gate application's replay needs it | Order unspecified upstream | Medium: an application that shows the array unsorted sees another order |
| R28.4 | **`topK` and `approx_top_k` are ClickHouse's Filtered Space-Saving** (`SpaceSaving.h`): exact while at most `max(64, 2 × reserved)` distinct values are seen, which covers the corpus. Values tied on `count - error` (then `count`) come first-seen first; ClickHouse's `partial_sort` leaves their order unspecified (measured: `topK(2)` and `topK(10)` break the same tie differently). Past the threshold the `alpha` map is indexed by a hash that is not ClickHouse's, so approximate counts can differ | Documented as approximate upstream | Low |
| R28.5 | **Float sums round as ClickHouse's do per block**: `AggregateFunctionSumData::addManyImpl`'s sixteen partial sums, then the tail, over each batch the accumulator receives (DataFusion's batches, not ClickHouse's blocks, so very large inputs may differ in the last bits; the corpus uses exact values). `avg` keeps an exact integer or decimal numerator and divides once; `avg` of `Date`, `Date32`, `DateTime` and `DateTime64` keeps the type, rounded half to even, as 26.9 does. Partial states are the engine's own Arrow layout (not ClickHouse's state bytes, which are Task 29); `partial_states_merge_as_one_pass` checks them across four partitions. No `GroupsAccumulator` yet: DataFusion runs one accumulator per group (Task 46 measures) | Oracle cases `sum_types`, `avg_types`, `avg_dates` | Low |
| R28.6 | **`aggregate_functions_null_for_empty` and `count_distinct_implementation` are settings, refused with `48` until Task 37 (D1805)**; the engine's answers are 26.9's defaults (`0` and `nan` on empty input; `uniqExact`'s count). Task 37 maps the first onto `-OrNull` appended to every aggregate name (then the R28.1 rewrite) | D1805 | None |
