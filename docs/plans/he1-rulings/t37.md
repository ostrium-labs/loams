# HE1 rulings, HE1 Task 37: Settings on the Rust engine (D1804)

Rulings made while executing Task 37 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R37.1, R37.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R37.1 | **Codes.** An unknown name is `115`; a setting the House never allows at that value (`use_query_cache = 1`, or a setting without a row at a value other than chDB's default, R9.11) is `164`, as the front answers. A setting that changes answers and whose task has not landed is `48` naming the task, not `164`: it is the engine's gap, and `prefer-rust` falls back to chDB on a `48` before the first byte (Task 39) | D1805, Review Focus 3 | Low: a client sees `48` where the front would have passed the setting to chDB |
| R37.2 | **A default-only setting is refused only where it applies.** Each row names the construct it changes (`outer_join`, `merge_tables`, `aggregate`, `time`, …); the engine reads the planned statement's shape and refuses a non-default value only when the construct is there. `join_use_nulls = 1` without an outer join, or `final = 1` over plain `MergeTree`, asks for nothing and is accepted. Detection is conservative (any text beside a time counts as a time conversion) | ClickHouse answers the same without the construct; Langfuse and OpenPanel send these on every query | A false negative would ignore a setting: the tests `scoped_settings_are_refused_only_where_they_apply` and `refused_settings_are_never_ignored` pin each scope |
| R37.3 | **`max_result_bytes` counts Arrow's buffer sizes** (`RecordBatch::get_array_memory_size`), not ClickHouse's column bytes. Near the limit the two can disagree | A cap, not an answer; the front's own cap still holds | Low: a result within a few percent of the limit may pass on one engine and fail on the other |
| R37.4 | **`result_overflow_mode = 'break'` is refused (`48`) while a result limit is set.** ClickHouse stops at a block boundary, which no other engine reproduces. `'throw'` is honoured (`396`) | Deterministic answers | None: `break` with no limit set asks for nothing |
| R37.5 | **chDB's defaults table moved to `loams-house-ipc`** (`policy::CHDB_SETTING_DEFAULTS`, `chdb_default`, `is_default`, `same_setting_value`), and the front re-exports them. The engine reads the same table without depending on the front. `SATISFIED_SETTINGS`, `FRONT_SETTINGS` and `LOAMS_SETTINGS` are copied into the engine's test, which reads the front's source text so they cannot drift | The task's rule: the engine depends on `loams-house-ipc`, never on `loams-house` | None |
| R37.6 | **`max_threads` maps to `target_partitions`; when a statement does not set it the engine keeps 1** (Task 23's default), so unordered answers keep a stable order for the oracle. `auto` and 0 are the cores. `max_block_size` maps to `batch_size` and `max_memory_usage` to DataFusion's memory pool (`241` past it, by DataFusion's accounting) | Speed only; the answer is the same | Low: a slower default until Task 46 tunes it |
| R37.7 | **`session_timezone` is honoured for written values and refused (`48`, Task 30) wherever the statement converts, compares or computes times**, until Task 30 reads `Settings::timezone`. `date_time_output_format` (`simple`, `iso`, `unix_timestamp`) is honoured in `loams_house_types::text` | Output is the engine's; conversions are Task 30's functions | None: refused, never ignored |
