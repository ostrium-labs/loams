# HE1 rulings, HE1 Task 38: Metadata: `system` tables, `SHOW`, `DESCRIBE`, `EXISTS`, safe table functions

Rulings made while executing Task 38 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R38.1, R38.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R38.1 | **Metadata statements are read on sqlparser's tokens, not its AST** (`loams-house-sql/src/meta.rs`). `SHOW TABLES` and `SHOW DATABASES` become the `SELECT` ClickHouse rewrites them into (`InterpreterShowTablesQuery`) and are planned as queries over `system.tables` / `system.databases`; `DESCRIBE`, `SHOW CREATE` and `EXISTS` are answered from the catalog (`Command::Meta`). `SHOW TABLES FROM` a missing database is `81` | sqlparser 0.62 reads these in MySQL's and Snowflake's grammars (`EXISTS DICTIONARY`, `SHOW CREATE t`, `NOT ILIKE … LIMIT` do not parse) | A form ClickHouse accepts and the token reader does not is `62`/`48`, never a wrong answer |
| R38.2 | **`ALIAS` columns of `system` tables are real columns** (`system.tables.table`, `columns.column`, `databases.database`, `parts.bytes`, `marks_size`, `part_name`), so `SELECT *` from a `system` table includes them | The front's chDB views are built from `DESCRIBE`, which lists them, so both engines show the same; `WHERE table = …` must work | `SELECT * FROM system.tables` has a few more columns than ClickHouse's; no gate application reads it that way |
| R38.3 | **The dev server fills the columns the front fills for chDB and leaves the rest at their defaults** (`uuid` is the zero UUID, `metadata_modification_time` is 1970-01-01, paths are empty). One part per `MergeTree`-family table with rows (`all_1_1_0`, partition `tuple()`); views have `NULL` sizes and no parts | Task 39 replaces the dev server's fill with the front's own rows (`TablePin::Inline`, `system::inline`); the dev server only needs the gate applications' reads to answer as on the oracle | A corpus case reading an unfilled column differs from the oracle by design; such cases are `incompatibility` entries |
| R38.4 | **`system.settings` is Task 37's `system_rows`**: every ClickHouse setting at the statement's value. `min`, `max`, `alias_for`, `is_obsolete` and `tier` print their defaults until chDB's defaults table gains those columns | Never invented; the table holds what the engine knows | Editors that show `min`/`max` show none |
| R38.5 | **Table functions:** `numbers`, `numbers_mt`, `zeros`, `zeros_mt` (and `system.numbers`, `numbers_mt`, `zeros`, `zeros_mt`, `one`) run, with number-literal arguments only. The matrix's `disabled` table functions are `344` at any case; `clusterAllReplicas(<cluster>, system.<t>)` reads `system.<t>` (R9.62), any other `clusterAllReplicas` is `344`; every other table function is `48` | D1558's deny list, held by the guard as well as the front (`disabled_table_functions_match_the_matrix`) | A constant expression argument (`numbers(1 + 2)`) is `48` where ClickHouse runs it |
| R38.6 | **The oracle seeds views as their rows and sends each table's metadata in `X-Loams-Table`** (`system.tables` keys and statements, `SHOW CREATE`, `DESCRIBE` columns with `system.columns`' key flags); the `X-Loams-Columns` list is the physical columns only (no `ALIAS`/`MATERIALIZED`/`EPHEMERAL`), matching `SELECT *` | R9.13's gap (`DESCRIBE` of a plain view) and `SHOW CREATE` need the oracle's text, and a table with an `ALIAS` column could not be seeded before | A view whose rows cannot be exported is skipped with a message, so cases on it are `60` on the engine |
