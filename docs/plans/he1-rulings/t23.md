# HE1 rulings, HE1 Task 23: The engine oracle

Rulings made while executing Task 23 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R23.1, R23.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R23.1 | **The development oracle uses a shared fixture directory and reloads `snapshot.json` per query.** The miner publishes a generation of metadata and Parquet atomically after baseline setup; `--fixtures` is required when a selected target has `seed_from`. Names become hex path components, and the reader rejects escaped paths. | Keeps the HTTP endpoint read-only and avoids adding a second upload protocol before Task 39. Fixture reload cost is acceptable for this development harness, not the production worker. | Low; Task 39 uses pinned lake views instead. |
| R23.2 | **Snapshot all non-system tables on the dedicated synthetic reference server, including evaluated alias columns.** Export uses an explicit column list from `system.columns`. Engine, sorting/partition expressions and defaults are preserved in the manifest. | Captures tables recreated by setup and avoids guessing table names by parsing DDL. ALIAS columns do not appear in `SELECT *`, so the export must name them explicitly. | Dedicated oracle server required; extra tables increase fixture size. |
| R23.3 | **`house-rust` is opt-in with `--only house-rust`; the HE1 corpus has its own manifest.** Empty case selection fails. `--task N` fails on unresolved task-assigned bugs while preserving HE0 triage behavior. | Existing HE0 runs must not require an unstarted Rust dev server or replay the new engine corpus. | Low. |
| R23.4 | **Minimal integer literal typing is brought forward from Task 24.** Integer literals use ClickHouse's smallest UInt8/16/32/64 or Int8/16/32/64 width before DataFusion planning. Broader arithmetic/coercion remains Task 24. | `SELECT 1` otherwise reports Int64 instead of the oracle's UInt8, preventing Task 23's first comparison from passing. | Covered by the live literal-width corpus and front-end regression tests. |
| R23.5 | **Local verification and GitHub exit gates are reported separately.** This change adds the per-PR workflow but does not promote it into `CI required` or claim its runtime before it runs green on `dev`. | The Task 23 exit includes GitHub execution evidence, which a local build cannot establish. | Required-check promotion remains pending that evidence. |
| R23.6 | **Parquet restoration follows the measured 26.9 encodings.** Enum labels become the declared Enum8/16 values, nested field layouts and metadata are restored recursively, and LowCardinality dictionaries are rebuilt. AggregateFunction columns export through `toString(column) AS column`, retaining their original type in metadata. | The live round trip found that Parquet exports enums as binary labels and refuses aggregate-state types directly. `toString` exposes ClickHouse's state bytes without finalizing them. | Covered by the seeded type/state comparison corpus. |
| R23.7 | **Local evidence, 2026-10-25:** the dev server and miner build without libchdb; 106 regression tests pass (one pre-existing live fixture recorder ignored), including `engine_crates_stay_apart`; strict Clippy on all engine/miner/front-end targets, formatting and `cargo deny check licenses sources bans` pass. The live digest-pinned ClickHouse 26.9.2.8 comparison passes all 11 cases with zero bugs, incompatibilities or untriaged mismatches. | Includes signed/unsigned literal widths, names, errors, empty results, seeded primitive/composite types, Enum8/16 and aggregate-state bytes. | GitHub runtime/required-check promotion is still unmeasured (R23.5). |
