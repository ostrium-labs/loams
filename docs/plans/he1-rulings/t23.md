| R23.1 | **Seeded targets.** A target with `seed = true` (`house-rust`, `loams-house-engine-dev` on 127.0.0.1:28126) gets no setup statements. After the baseline has run a corpus's setup, `loams-house-mine` (`oracle/seed.rs`) copies every table of the baseline's current database to it: `system.tables` (engine, sorting key), `system.columns` (names, ClickHouse types) and `SELECT * FORMAT Parquet`, posted to `/loams/seed`. The engine converts ClickHouse's Parquet layout to its own (`loams_house_engine::seed::to_engine`): `Enum` names to values, integer `DateTime`/`DateTime64` ticks to timestamps, plain values to `LowCardinality` dictionaries, recursively through arrays, maps and tuples. Measured: every Tier 0 type of `corpus/he1/21` seeds and reads back identically (values and types) | D1804 | Low |
| R23.2 | **The dev server** (`loams_house_engine::server`) is a loopback-only HTTP/1.1 server written on `std::net`, one thread per connection: `/ping`, `POST /` (body and `query`, `database`, `param_*`, settings), and `/loams/seed`. It answers in `JSONCompactEachRowWithNamesAndTypes` only, until Task 36. Errors come back as ClickHouse's: a non-200 status, `X-ClickHouse-Exception-Code`, and `Code: N. DB::Exception: … (NAME)`. The binary refuses a non-loopback `--listen` and is never in a release image | Plan HE1 Task 23 | Low |
| R23.3 | **Types in `JSONCompact*` headers are on one line.** Measured: the oracle writes `Tuple(a UInt8, b String)` there, not `toTypeName`'s multi-line form, so the writer uses `ChType::to_compact_string` | Oracle run, `he1-21/composites` | Low |
