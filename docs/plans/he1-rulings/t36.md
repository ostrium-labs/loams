# HE1 rulings, HE1 Task 36: Output formats (`loams-house-formats`)

Rulings made while executing Task 36 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R36.1, R36.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R36.1 | **Writers take the format settings; the engine gets the rest.** `FormatSettings::split` takes the writer-only settings (`output_format_native_write_json_as_string`, `output_format_write_statistics`, the Pretty, CSV and TSV ones) out of a request (HTTP parameters on the dev server) and leaves the others for the engine; the value-text settings (`output_format_json_*`, `output_format_decimal_trailing_zeros`, `date_time_output_format`, `session_timezone`) are resolved by Task 37's `Settings` and reach the writer as `Settings::text()`. A writer-only setting in a `SETTINGS` clause is still refused by the engine. | A format setting is honoured where it is used; nothing is silently ignored | Low: Task 37 moves the split into its settings table |
| R36.2 | **`Parquet`, `Arrow` and `ArrowStream` carry the engine's Arrow layout**, every field keeping `loams.ch.type`, not ClickHouse's own Parquet/Arrow type mapping (`Date` as `UInt16`, strings as `Binary`, …). They are checked by reading back (`parquet_reads_back_identically`), never byte for byte, and the `he1/36` corpus has no byte cases for them. | Another writer's encodings and statistics cannot match ClickHouse's bytes; values and types are what clients read | Medium: a client that relies on ClickHouse's Arrow type mapping needs a mapping step (HE2) |
| R36.3 | **`Native` dictionaries are rebuilt per block**: a `LowCardinality` column is written as one granule whose dictionary is `NULL`'s placeholder (for `Nullable`), the default, then the values in order of first occurrence, as a fresh `ColumnUnique` holds them. An empty result in `Native` is its header block. Totals and extremes are not written in `Native`, `RowBinary`, `JSONEachRow`, `Values`, `Parquet` or `Arrow`. | The layout the native codec's oracle fixture shows (`loams-house-native` `low_cardinality_for_old_clients`) | Medium: the `he1/36` byte cases decide; the empty-result header is the least certain |
| R36.4 | **`Pretty*` renders once, at the end**, up to `output_format_pretty_max_rows`, without colour (HTTP is not a terminal), with row numbers and the single-large-number tip. Multi-line values, the footer of names and wide characters are not done yet. | ClickHouse squashes the engine's blocks into one table (`output_format_pretty_squash_consecutive_ms`) | Low: presentational formats; the corpus shows any difference |
