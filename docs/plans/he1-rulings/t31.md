# HE1 rulings, HE1 Task 31: Functions II: strings, regular expressions, hashes, UUIDs, IPs

Rulings made while executing Task 31 of [plan HE1](../2026-10-21-he1-loams-house-engine.md), numbered R31.1, R31.2, …. Add a row at the end; never renumber. One file per task, so parallel PRs do not conflict.

| R31.1 | **Functions are `ChFunction`s (`loams-house-exec/src/func/chudf.rs`) with ClickHouse's default implementations around a kernel over plain arrays.** A `Nothing` argument (literal `NULL`) gives `Nullable(Nothing)`; a `Nullable` argument gives a `Nullable` result, `NULL` on rows with a `NULL` argument; when every non-constant argument is `LowCardinality` the result is `LowCardinality` (`length(lc)` is `LowCardinality(UInt64)`), all as measured. Each result field carries `loams.ch.type`, so the output names `UUID`, not `FixedString(16)`. Predicates (`like`, `match`, `startsWith`, `multiSearchAny`, …) answer `UInt8`, as ClickHouse. A `UInt8` predicate inside `WHERE` needs Task 24's boolean contexts; until it merges, those cases are `bug` entries of Task 24. `length` takes strings, arrays and maps in one function, so Task 32 extends it rather than registering another | Plan HE1 Task 31 | Low |
| R31.2 | **The engine's `String` is Arrow `Utf8` (R21.3), so a byte-wise result that would split a UTF-8 character is refused with `48`, never answered differently**: `left('ä', 1)`, `substring` mid-character, a `trimBoth` set naming part of a character, and `replaceRegexpAll` with an empty match inside a multi-byte character (ClickHouse writes the invalid bytes). Whole-character and ASCII results are exact | R21.3 | Medium: goes away if `String` becomes `Binary` (HE2) |
| R31.3 | **RE2 patterns are translated, not passed through**, to the `regex` crate's syntax (`func/strings/re2.rs`), in ClickHouse's mode: UTF-8, `.` matches `\n` (measured: `match('a\nb', 'a.b')` is 1). Differences rewritten: `\d \w \s \b \B` are ASCII in RE2 (`\s` without `\v`), Unicode in `regex`; inside a class `[`, `&&`, `--`, `~~` are literals in RE2 and set operations in `regex`; `\<` `\>` are literals in RE2 and word boundaries in `regex`; `{` not starting a repetition is a literal in RE2 (`a{,2}`); `\Q…\E` is RE2-only. RE2's rejections are `427 CANNOT_COMPILE_REGEXP`: repetition counts over 1000, `a**`, `a{2}{3}`, unknown escapes (`\Z`, a lone `\1`), flags other than `imsU`, look-around. Constructs RE2 takes but `regex` cannot express the same way are `36 BAD_ARGUMENTS`: `\C`, octal escapes, `\p{…}` names other than general categories and RE2's scripts. `LIKE` becomes an anchored regex: `%`, `_` (one character), `\%`, `\_`, `\\`; a backslash before anything else is a literal backslash and that character; a trailing backslash is `25`; `ILIKE` folds case as RE2 does (`'K' ILIKE 'k'`, not `'ß' ILIKE 'SS'`) | Plan HE1 Task 31 | Medium: a construct outside this list may differ; each new oracle case checks one more |
| R31.4 | **`cityHash64` is a port of CityHash v1.0.2's `CityHash64` and `Hash128to64`** (`func/hash/city.rs`, MIT, `NOTICE`), as ClickHouse vendors it (`contrib/cityhash102`); `cityhash-rs =1.0.1` is 128-bit only and later CityHash versions changed the function. `xxHash32`/`xxHash64` use `twox-hash` (MIT) and `sipHash64` uses `siphasher` (SipHash-2-4, zero keys; MIT OR Apache-2.0). Variadic hashing follows `FunctionAnyHash`: per ClickHouse type, numbers by their in-memory bytes (`cityHash64`: `intHash64` of the zero-widened bits), arrays as `intHash64(length)` then each element combined, maps as arrays of (key, value), tuples flattened; combiners are `Hash128to64` (city, xx64), `intHash32(h1) ^ h2` (xx32) and SipHash of the 16 bytes (sip). Bit-exact on the fixtures (`hashes_match_the_oracle`, 27 lengths × 4 functions). A `NULL` inside an array or map is refused (`48`): ClickHouse's answer there is not measured yet | Plan HE1 Task 31 | Low |
| R31.5 | **`POSITION(n IN h)`, `SUBSTRING(s FROM a [FOR b])`, `TRIM(BOTH c FROM s)` (and `LEADING`, `TRAILING`), `trim(s, c)`, `LIKE`, `NOT LIKE`, `ILIKE` and `NOT ILIKE` are rewritten by the guard into `position(h, n)`, `substring`, `trimBoth/trimLeft/trimRight`, `like`, `notLike`, `ilike`, `notILike`**, the functions ClickHouse reads them as (its own `EXPLAIN SYNTAX`), so they get ClickHouse's semantics instead of DataFusion's. `TRIM(c FROM s)` and `SUBSTRING(s FOR n)` are `62`, as in ClickHouse. `LIKE … ESCAPE` stays `48` | Plan HE1 Task 31 | Low |
