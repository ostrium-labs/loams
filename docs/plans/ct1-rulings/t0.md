## R0.2 `h3` has no release since 2025-05-06

`hyperium/h3` is active: it is not archived, and the last push was 2026-10-08. But 0.0.8 is 17 months old, and later fixes on `main` are unreleased. Two of them matter to us:
- #360: flush data buffered by `send_data` before the next write and before `finish`;
- #365: release request tracking when the resolver ends early.

Ruling:
- Pin 0.0.8 and 0.0.10 from crates.io.
- Task 2's spike tests specifically for the #360 symptom: a truncated tail on a streamed response that ends with `finish` right after `send_data`.
- If the spike hits #360 or #365, the fallback is a git pin of `hyperium/h3` at a commit at least 14 days old. That requires adding an `allow-git` entry to `deny.toml`, and the change is recorded here.
- This is the "library maturity" cost in §83 §11. It also weighs on Q1471: `s2n-quic-h3` 0.2.2 was released 2026-08-14, so it is maintained more actively.

## R0.3 `connectrpc` serves through `tower::Service`

`connectrpc` 0.9.1 implements `tower::Service<Request<B>> for ConnectRpcService<D>` (`src/service.rs`). It depends on `tower` 0.5 and optionally `axum` 0.8. One Connect service can therefore sit behind both the HTTP/2 (hyper) and the HTTP/3 (h3) accept loops, as §83 §3 assumes.

What `loams-transport` must add: an adapter from an `h3::server::RequestStream` to `http::Request<B>` and back, with the request and response bodies streamed. This is the main code of Task 2.

## R0.4 QUIC's TLS uses aws-lc-rs, not ring

`quinn` 0.11.12 has the `rustls-aws-lc-rs` feature. With default features off and that feature on, `quinn`'s crypto (`quinn-proto`'s `rustls` integration) uses aws-lc-rs, which is the same provider as the workspace's TLS. `iggy` already pulls `quinn`. Task 3 checks with `cargo tree -e features -i ring` that turning the feature on adds no new `ring` path. `ring` stays in Cargo.lock through other crates, which is unrelated.

## R0.5 TiKV and PD authorize clients by Common Name

TiKV and PD's `[security]` take `ca-path`, `cert-path`, `key-path` and `cert-allowed-cn`. `cert-allowed-cn` checks the certificate's **Common Name**, not the URI SAN (verify against TiKV v8.5.8's docs in Task 9).

Ruling: leaves for the TiKV and PD hops also carry a CN equal to the identity's last segment: `tikv`, `pd`, `tidb`, or `loams-node-<id>` for engine clients. `cert-allowed-cn` lists those names. Loams' own route policy keeps reading the URI SANs (D2308).
