# CT1 Task 3 — `loams-transport`: identity and the CA service (rulings)

## Part 1 (2026-10-29): identities, mTLS configurations, peer identity

This part adds the new crate `crates/loams-transport` (`publish = false`). Nothing in the product uses it yet.

- `SpiffeId` parses and formats the D2308 IDs: `spiffe://<cluster>/<node|role|svc>/<name>`.
  - It follows SPIFFE's trust-domain and segment character rules, with a maximum length of 2048 bytes.
  - It uses exactly two path segments.
  - `short()` (`role/gateway`) is the form route policies will name (Task 4).
- `tls::server_config` and `tls::client_config`:
  - TLS 1.3 only, with aws-lc-rs as an **explicit** provider (`builder_with_provider`), so the configs do not depend on any process-wide default provider;
  - client certificates are required on the server side (`WebPkiClientVerifier`);
  - one ALPN per config (`h3` or `h2`);
  - `max_early_data_size = 0` on the server and `enable_early_data = false` on the client (D2318).
- `peer::peer_identity` reads every SPIFFE URI SAN from a verified leaf, so a node certificate can carry `node/` plus its `role/` IDs. It refuses a certificate whose IDs name more than one cluster.

**R3.1 Crypto provider split.** `crates/loams` builds its existing TLS (the House link and the main-port TLS of `tls.rs`) on **ring** (`rustls` `ring` feature, `tokio-rustls` `ring`). `loams-transport` uses **aws-lc-rs** (D2306).
- Both providers can live in one binary because each config names its provider explicitly.
- Moving `crates/loams`' own TLS to aws-lc-rs is a separate change for T1 (Task 6), done when the cluster listener moves onto `loams-transport`. It is not done here.

Tests (`cargo test -p loams-transport`, 8 in total):
- `round_trips_every_kind` and `refuses_what_is_not_an_identity`;
- in-memory handshakes (no sockets), for `h3` and `h2`: `mutual_tls_names_the_peer_on_both_sides`, `a_client_from_another_ca_is_refused`, `a_client_without_a_certificate_is_refused`;
- `a_certificate_without_a_spiffe_id_has_no_identity`, which also refuses mixed clusters;
- `zero_rtt_is_off_on_both_sides` and `an_empty_bundle_is_an_error`.

Clippy passes with `-D warnings`. Buck is regenerated.

## Part 2a (2026-10-30): the CA, join tokens, identities and the deny list

This part is still library code. Nothing in the product uses it yet. The service, the CLI and the metastore storage come in part 2b.

- **`Identity`** holds a process's chain, key and bundle.
  - Its validity comes from the leaf, and `renew_at` is two-thirds of the leaf's life (D2309).
  - `server_config` and `client_config` wrap `tls`.
  - `from_pem_files` reads the `tls.crt`/`tls.key`/`ca.crt` layout used by cert-manager and SPIRE (D2314).
  - `Debug` redacts the key.
- **`ca::Ca`**:
  - `init`: a P-256 root (10 years) and an intermediate (1 year, path length 0), returned as `CaMaterial` PEM. Its `Debug` redacts both keys.
  - `load`: needs only the intermediate's key.
  - `issue(csr, grant, serial, now)` signs a 24-hour leaf.

**R3.2 The CA builds every leaf from scratch.** From the CSR it copies only:
- the public key;
- the SPIFFE URI SANs, each of which must be in the `Grant` and in the CA's cluster;
- the DNS and IP SANs.

It never copies the CSR's CA bit, key usages, EKUs or validity. The test `a_csr_asking_to_be_a_ca_gets_a_plain_leaf` covers this.

**R3.3 Validity windows.** `notBefore` is backdated 5 minutes (`BACKDATE`) to absorb clock skew between nodes (§83 §15). Renewal is two-thirds of the whole window, backdate included.

**R3.4 Serials.** The CA reports the serial as the certificate encodes it: DER drops leading zero bytes. The deny list and `Identity::serial` compare these bytes.

- **`new_key_and_csr`** makes the key and CSR in the requester's memory (D2311). Only the CSR travels to the CA.
- **`token::JoinToken`**: `loamsjt1.<id>.<32-byte secret>`, URL-safe base64.
  - The CA stores only the secret's SHA-256, in a `TokenRecord`.
  - `TokenStore::redeem` checks the secret in constant time and spends the token in the same step.
  - A token lives one hour.
  - `MemoryTokens` is the test store. The metastore store comes in part 2b.
- **`DenyList`** revokes by serial or by SPIFFE ID (D2312).
- **API stability**: the crate-root re-exports are the API that design 85 (the desktop's QUIC streaming) and CT1 Task 6 build on. Changes are additive. Anything breaking needs a CT1 ruling.

Tests:
- `tests/ca.rs` (8): the join flow ending in mTLS over h3 and h2; the 24-hour and two-thirds schedule; a token used twice, an expired one and a wrong secret; grant, cluster and CSR refusals; a CSR asking for a CA certificate; the deny list by serial and by identity; keys never printed; PEM loading.
- Part 1's 8 tests also run.
- Clippy with `-D warnings` is clean.
