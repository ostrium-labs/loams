# CT1 Task 2: stack spike (report, 2026-10-29)

The spike is in `bench/transport/spike`. It is a workspace of its own, not a member of the root workspace (`bench/meter` is set up the same way). It serves one axum `Router` (a `tower::Service`) two ways from the same port number, both with mTLS from a throwaway P-256 CA whose leaves carry SPIFFE URI SANs:
- over HTTP/3 on UDP, with `quinn` 0.11.12 (`rustls-aws-lc-rs`, default features off), `h3` 0.0.8 and `h3-quinn` 0.0.10;
- over HTTP/2 on TCP, with hyper 1 and tokio-rustls.

Both sides run TLS 1.3 only, with 0-RTT off. The lockfile is seeded to the workspace's `aws-lc-rs` 1.18.1 and `rustls` 0.23.46.

## What fits

- **One service, two transports.** The axum router, and therefore any `tower::Service` including `connectrpc`'s (R0.3), runs unchanged under both. The HTTP/3 side needs about 30 lines: an adapter from `h3::server::RequestResolver` to `http::Request<Body>` and back. The peer identity goes into request extensions on both sides.
- **mTLS works on both transports.** A client certificate from a foreign CA is refused over HTTP/3 and over HTTP/2 (`refuses_foreign_ca: {h3: true, h2: true}`). On QUIC the peer's chain comes from `Connection::peer_identity()`, and on TCP from `ServerConnection::peer_certificates()`. The SPIFFE URI is parsed with `x509-parser`.
- **No `ring` is needed for QUIC.** `quinn` with `rustls-aws-lc-rs` builds and runs on aws-lc-rs alone.
- **h3 #360 did not show up.** Each 64 MiB response arrived with an exact byte count (3 runs per transport), so the crates.io pins stand (R0.2).
- **It built first time** against `h3` 0.0.8's `RequestResolver` API and `rcgen` 0.14's `Issuer`.

## Smoke numbers

These come from loopback with the client and server in one process, `taskset -c 8-11`, on a laptop that was busy with other builds. They are **not** Task 11's benchmark and must not be quoted as results.

| | Handshake p50 / p99 (ms) | Unary 1 KiB, 64 in flight (rps) | Unary p50 / p99 (ms) | 64 MiB stream (Gbit/s) |
|---|---|---|---|---|
| HTTP/3 + mTLS | 2.34 / 2.75 | 73,204 | 0.83 / 1.70 | 5.6–6.0 |
| HTTP/2 + TLS 1.3 + mTLS | 1.85 / 2.29 | 77,359 | 0.74 / 1.23 | 11.8–12.4 |

What the numbers suggest:
- For small RPCs (class C), HTTP/3 is close to HTTP/2: 5% lower rps and a 0.5 ms worse p99.
- For bulk transfer on loopback (class B), HTTP/3 gets about half of HTTP/2's throughput. That is the user-space CPU cost §83 §11 expects, before any GSO/GRO or window tuning. Loopback has no loss, and that is exactly where TCP is strongest.
- Task 11 must measure CPU per byte and run with loss and RTT (class A) before any ruling.
