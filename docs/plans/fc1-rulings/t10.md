# FC1 Task 10 — The planner (fork PR #16, part 1; 2026-10-30)

- **R10.1 No JVM fallback.** StreamFusion's Java encoder hands every expression it cannot evaluate natively back to Flink's generated code. Loams Stream has no JVM, so the Rust port (`loams-stream-plan::encode`) admits only the encoder's native paths and fails anything else with a named feature (D2268). It never evaluates an expression approximately. Casts and functions that StreamFusion runs through the JVM (float and decimal to string, `TO_TIMESTAMP`, `JSON_*`) need new engine kernels, one by one.
- **R10.2 Engine kernels added by Loams Stream use op codes from 900.** The first is `TO_TIMESTAMP(string)` with Flink's default format (op 900). StreamFusion's codes below 900 keep their meaning.
- **R10.3 The session time zone is UTC.** `TO_TIMESTAMP_LTZ`, `EXTRACT` and `DATE_FORMAT` over `TIMESTAMP_LTZ` are evaluated in UTC, the zone the harness sets (`table.local-time-zone = UTC`). Other zones are planned with the session configuration in Task 19.
- **R10.4 String comparisons are admitted.** Flink orders strings by their UTF-8 bytes (`BinaryStringData.compareTo`), as Rust does. StreamFusion refused them for its JVM string representation, which Loams Stream does not have.
- **R10.5 Timestamps compare as their components.** A `TIMESTAMP` or `TIMESTAMP_LTZ` is a `(millis, nano_of_milli)` struct in the engine (R4.3). DataFusion compares structs field by field, which is the timestamp order. A `TIMESTAMP` against a `TIMESTAMP_LTZ` needs a zone and is not admitted.
- **R10.6 A local executor stands in for the runtime.** `loams-stream-runtime::local` runs a plan in one thread over bounded sources, with a watermark after each source batch. Task 11 replaces it. Restore cases read `data/` and then `data-after-restore/` in one job, with a watermark per row, until savepoints exist (Task 14).
- **R10.7 The FC1 bar's 180 cases** are the recorded Flink test programs whose operators are all FC1 in `conformance/profile.toml`. They include the 41 `oracle-differs` cases, whose reference is the oracle's own recording. Cases the oracle could not run are excluded. This is the count the FC0 exit report used.
- **R10.8 Legacy group windows are in FC1's bar.** `GROUP BY TUMBLE/HOP/SESSION(...)` (`GroupWindowAggregate`) is FC2 in the profile, but Nexmark q11 uses it and Nexmark is in FC1's bar. The planner names it as an FC1 feature.
- **R10.9 Build environment.** The system's GCC 16 fails to build `librocksdb-sys` 0.16, whose header lacks `<cstdint>`. Workspace builds use `CXXFLAGS="-include cstdint"`. This is an environment setting only, with no code change.
- **R10.10 Session windows and interval joins.**
  - A partitioned `SESSION` TVF groups by its partition keys, as its aggregate does.
  - A join whose condition bounds one rowtime by the other is an interval join, with the bounds normalised to `lower <= left.rt - right.rt <= upper`.
