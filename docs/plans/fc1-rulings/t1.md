# FC1 Task 1 — Version bump, toolchain and crate skeletons (fork PR #1, merged 2026-10-29)

- **R1.1 Pins.** `datafusion` 54.1.0, `arrow`/`arrow-*`/`parquet` 58.4.0 (58.4.1 is held back as under 14 days old), `sqlparser` 0.62.0, Rust 1.97.1 with rustfmt and clippy. The bump needed no source changes. The release Dockerfile moved to `rust:1.97.1-bullseye`.
- **R1.2 The `jni` feature.** Default-on in the engine (`streamfusion`) and in `streamfusion-bridge`. Without it, every `Java_*` entry point, `JNI_OnLoad`, the log bridge and the RocksDB JNI lifecycle are compiled out. JVM callback objects get an uninhabited type, so the JVM-only paths cannot run and do nothing silently; JVM UDFs and the JVM memory authority return errors. The Maven build uses default features and is unchanged. `standalone_graph_has_no_jni` guards the `loams-stream` binary.
- **R1.3 Crates.** Skeletons `loams-stream-{sql,plan,runtime,coord,rest,connectors,udf,conformance}` and the binary `loams-stream`, edition 2024, Apache-2.0, version `0.1.0-preview.1`. `--role` defaults to `all` when omitted.
- **R1.4 Provenance.** `PORTS.md` (empty table) and a NOTICE entry for StreamFusion's authors and the fork commit.
- **R1.5 Scheduled workflows.** `flink-suite.yml` and `fork-ci-status.yml` lost their cron triggers. Fork #4 then trimmed CI further: on PRs and pushes to `main`, only the native build, the Rust tests with `clippy -D warnings`, and Java tests for Flink 2.2 on JDK 17 run; everything else is `workflow_dispatch` only.
- **R1.6 Local builds.** RocksDB 8.10 needs `CXXFLAGS="-include cstdint"` under GCC 15. CI's GCC does not need it.
- **R1.7 Inherited lint findings (amended in #8, ruling R4.5).** Clippy over the inherited crates used to fail; #8 allows those findings per crate.
