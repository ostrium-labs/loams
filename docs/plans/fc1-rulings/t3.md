# FC1 Task 3 — The Flink SQL parser (fork PR #3, merged 2026-10-29)

- **R3.1 sqlparser.** Pinned to 0.62.0 with the `visitor` feature (Task 0, R0.2).
- **R3.2 `ADD JAR`/`REMOVE JAR`** are refused with a named feature (planned FC2, with the JVM UDF host). Flink's `.q` files run them successfully, so the `.q` test counts them separately. `SHOW JARS` parses.
- **R3.3** `MATCH_RECOGNIZE ... WITHIN` and the SQL/JSON clauses (`RETURNING`, `ON EMPTY`/`ON ERROR`, `KEY ... VALUE`, `IS JSON`) are refused by name: sqlparser 0.62 has no place for `WITHIN`, and the JSON clauses need their own nodes. Neither occurs in the `.q` files or in Nexmark.
- **R3.4** Materialized tables and models are refused by name as FC3 features (design 82 §4.1).
- **R3.5** Compound column names in `CREATE TABLE` (`a.b INT`) are a syntax error here. Flink's grammar accepts them, and its validator rejects them.
- **R3.6** `SET 'table.sql-dialect' = 'hive'` and Hive-only DDL (`TBLPROPERTIES`, `STORED AS`, `ROW FORMAT`) are refused as "Hive dialect, not built" (D2274).
- **Corpus result:** of the 806 statements in the 23 `.q` files, 790 parse. 9 are rejected exactly where Flink rejects them, and 7 are named refusals (`ADD`/`REMOVE JAR`). All 56 Nexmark statements parse, and 882 statements round-trip through print and re-parse.
