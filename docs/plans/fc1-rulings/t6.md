# FC1 Task 6 — The corpus (fork PRs #6 WIP and #11, 2026-10-29)

- **R6.1 Extraction.** Reflection over Flink 2.2.1's `flink-table-planner` test jar found 70 classes and 345 programs. 319 were exported as 330 cases. 26 were not exported, each with a reason in `manifest.json`: `ML_PREDICT` ×9, inline Table API functions ×12, non-string map keys in JSON ×4, a temporal table function ×1. `extractor_covers_every_program` checks the manifest.
- **R6.2 Nexmark seeding.** Upstream Nexmark is unseeded. Loams' generator seeds each event from its id, the way Apache Beam's Nexmark does; with seed 0 it follows upstream's logic but not any upstream byte stream. Approved under the owner's defaults rule. q10, q12, q13 and q14 are adapted (see `dev/corpus/nexmark/README.md`); q6 is expected to fail on Flink too.
- **R6.3 Restore cases.**
  - The runner drives Flink's restore programs this way: run on `data/` until the sink holds `restore_before_rows` change events, `STOP JOB ... WITH SAVEPOINT`, add `data-after-restore/` under new file names, set `execution.state-recovery.path`, re-run, wait for `before + after` events, then stop with drain (or without drain for `restore_end = "cancel"`).
  - A row-format filesystem sink finalises part files only on roll, so the restore flow also counts and reads in-progress part files. Flink truncates those to the checkpoint on restore.
- **R6.4 UDF cases** (`requires = ["flink-test-udfs"]`): the target supplies the jar with `--jar flink-test-udfs=<path>`, and the runner issues `ADD JAR`. A target without it reports `skipped`.
- **R6.5 Self-check.** The oracle's result and the expectation of Flink's own test program (`flink-expected.json`) are each folded into a final table (by primary key, else as a multiset), then compared as Java-rendered row texts. A difference is the verdict `oracle-differs`, and `record` lists it in `oracle-xfail.toml`.
- **R6.6 Executable `.q` cases are deferred to Task 22.** They need Flink's test artefacts (the UDF jar built by Flink's tests, the test `values` connector, test catalogs). Until then the `.q` files are covered by the parser and binder tests in `loams-stream-sql`. Approved under the owner's defaults rule.
- **R6.7** `EXECUTE STATEMENT SET BEGIN ... END;` stays one statement when scripts are split.
