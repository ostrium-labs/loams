# FC1 Task 4 — Binder and Flink's type system (fork PRs #7 WIP, #8, #9; 2026-10-29)

- **R4.1 `CAST` rules.** Flink's SQL `CAST` of an atomic type is checked by Calcite's `canCastFrom` with `FlinkSqlTypeMappingRule`, not by `LogicalTypeCasts`, and the two disagree (`INTERVAL` to `DECIMAL`/`BIGINT`; `BOOLEAN` to `DOUBLE`). The binder follows what users see: the SQL validator's check plus a runtime cast rule existing. `tests/golden/cast_matrix.tsv` records the combined verdict.
- **R4.2 Catalog home.** The `Catalog` trait and the in-memory catalog live in `loams-stream-sql::binder`. Persistent catalogs (the Iceberg REST catalog `loams`, JDBC, the Postgres catalog store) implement that trait in `loams-stream-plan` (Task 19, FC2).
- **R4.3 Arrow mapping.** It follows the engine's transport (`ArrowConversion`), not the plan's first sketch:
  - `TIMESTAMP`/`TIMESTAMP_LTZ` → struct `<millis Int64, nano_of_milli Int32>`, which covers Flink's full range;
  - `TIME` → `Time32(ms)`;
  - intervals → `Int32` months and `Int64` milliseconds;
  - `MULTISET` → a map from element to `INT` count;
  - `BINARY` → `Binary`.
- **R4.4 Decimals.** Every decimal maps to `Decimal128`; Flink's maximum precision is 38. Multiplication gives `DECIMAL(p1 + p2 + 1, s1 + s2)`, as Flink's `findMultiplicationDecimalType`.
- **R4.5 Inherited lint findings.** StreamFusion's clippy and rustc findings are allowed per crate in `[lints]` sections, so `clippy --workspace --all-targets -D warnings` is clean while the new `loams-stream-*` crates stay strict. The engine's test module gets a scoped `#![allow(unused_must_use)]`. They are to be fixed incrementally, tracked as a cleanup item for FC2. #8 also fixed the ignored `Result` in Top-N restore: the restore now fails loudly.
- **R4.6 Feature unification.** The engine's `HostObject` follows the engine's own `jni` feature, not the bridge's. A build that turns on the bridge's `jni` through another crate no longer breaks the no-jni engine.
- **R4.7 Permissive binder.** Where Flink's coercion is wide (character to numeric, comparisons), the binder accepts rather than risk refusing valid SQL; the oracle catches the difference. Unknown functions use Flink's wording. User functions are refused by name (FC2). Catalog types from user jars are refused by name (FC3), and so is any later `USE` of such a catalog.
- **Result:**
  - Over the `.q` files: 700 statements bound, 39 rejected as Flink rejects them, 28 named refusals, 0 failures.
  - Over Nexmark, everything binds except two. q14 uses a Java UDF and is refused by name. q6 is rejected; its `WHERE` uses a `SELECT` alias, and Flink rejects it too.
  - Not done: `ORDER BY` expression typing, and a live cross-check of the cast matrix against Flink (this moves to Task 7).
